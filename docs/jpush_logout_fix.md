# 极光推送退出登录修复

## 问题描述

**现象：** 用户退出登录后仍然能收到极光推送通知

**预期：** 
- ❌ 退出登录后不应收到针对该用户的定向推送
- ✅ 退出登录后仍可接收广播推送（如系统公告）

## 问题分析

### 极光推送的三种推送方式

1. **别名推送（Alias Push）**：通过用户别名（如用户ID）进行精准推送
   - 用途：针对特定用户的消息（如"对方锁定了手机"）
   - 退出登录后：❌ 应该清除

2. **RegistrationId推送**：通过设备唯一标识符直接推送
   - 用途：设备级别的推送
   - 退出登录后：✅ 保留

3. **广播推送（Broadcast）**：向所有设备推送
   - 用途：系统公告、活动通知等
   - 退出登录后：✅ 保留

### 之前的实现问题

退出登录时**调用了 stopPush()**，导致：
- ❌ 推送服务完全停止
- ❌ 无法接收任何推送，包括广播推送
- ❌ 需要重启应用或重新登录才能恢复

```dart
// 之前的实现（过度清理）
void _clearJPushAlias() {
  jpushService.deleteAlias();  // ✅ 删除别名
  jpushService.stopPush();     // ❌ 停止了所有推送（包括广播）
}
```

## 解决方案

### 退出登录时：只清除别名，保留推送服务

```dart
void _clearJPushAlias() {
  // ✅ 只删除别名（清除针对该用户的定向推送）
  await jpushService.deleteAlias();
  
  // ✅ 保留 RegistrationId：设备ID不变
  // ✅ 保留推送服务：仍可接收广播推送
  // ❌ 不调用 stopPush()
}
```

### 重新登录时：设置新别名

```dart
void _setJPushAlias(LoginModel user) {
  // ✅ 推送服务已在运行，无需调用 resumePush()
  
  // ✅ 设置新别名（用于精准推送）
  await jpushService.setAlias(alias);
}
```

## 推送场景分析

| 推送类型 | 退出登录前 | 退出登录后 | 说明 |
|---------|-----------|-----------|------|
| **别名推送** | ✅ 接收 | ❌ 不接收 | 清除别名后无法定向推送 |
| **RegistrationId推送** | ✅ 接收 | ✅ 接收 | 设备ID保持不变 |
| **广播推送** | ✅ 接收 | ✅ 接收 | 系统公告等仍可接收 |

### 典型应用场景

**1. 定向推送（需要登录）**
```
服务器 → 通过别名推送 → "对方在***锁定了手机"
状态：登录时 ✅ 接收 | 退出后 ❌ 不接收
```

**2. 广播推送（无需登录）**
```
服务器 → 广播推送 → "系统升级公告"
状态：登录时 ✅ 接收 | 退出后 ✅ 接收
```

**3. 设备推送（无需登录）**
```
服务器 → 通过RegistrationId推送 → "您的设备有新活动"
状态：登录时 ✅ 接收 | 退出后 ✅ 接收
```

## 修改内容

### `lib/network/public/auth_service.dart`

#### 修改：只清除别名，不停止推送服务

**修改前：**
```dart
/// 清除极光推送别名并停止推送服务
void _clearJPushAlias() {
  Future.microtask(() async {
    // 1. 删除别名
    await jpushService.deleteAlias();
    
    // 2. 停止推送服务 ❌
    await jpushService.stopPush();
  });
}
```

**修改后：**
```dart
/// 清除极光推送别名（仅清除定向推送，保留广播推送能力）
void _clearJPushAlias() {
  Future.microtask(() async {
    // 只删除别名（清除针对该用户的定向推送）
    // ✅ 删除别名：不再收到通过别名发送的定向推送
    // ✅ 保留 RegistrationId：设备ID不变
    // ✅ 保留推送服务：仍可接收广播推送
    bool aliasSuccess = await jpushService.deleteAlias();
    if (aliasSuccess) {
      logger.info('极光推送别名清除成功（保留广播推送能力）');
    } else {
      logger.w('极光推送别名清除失败');
    }
    
    // ❌ 不调用 stopPush()
    // 原因：退出登录后仍需要接收广播推送（如系统公告等）
  });
}
```

#### 登录时设置别名（无需改动）

```dart
/// 设置极光推送别名
void _setJPushAlias(LoginModel user) {
  Future.microtask(() async {
    // ✅ 推送服务已在运行，无需 resumePush()
    
    // 设置别名为用户ID
    String alias = user.id.toString();
    bool success = await jpushService.setAlias(alias);
    if (success) {
      logger.info('极光推送别名设置成功: $alias');
    } else {
      logger.w('极光推送别名设置失败');
    }
  });
}
```

## 工作流程

### 1. 应用启动

```
应用启动
  ↓
初始化极光推送（initJPush）
  ↓
推送服务运行中
  ↓
✅ 可接收广播推送
❌ 无别名，不接收定向推送
```

### 2. 用户登录

```
用户登录成功
  ↓
调用 _setJPushAlias(user)
  ↓
设置别名 = 用户ID
  ↓
✅ 可接收广播推送
✅ 可接收定向推送（通过别名）
```

### 3. 用户退出登录

```
用户退出登录
  ↓
调用 _clearJPushAlias()
  ↓
删除别名
  ↓
✅ 可接收广播推送（推送服务仍在运行）
❌ 不接收定向推送（别名已删除）
```

### 4. 用户重新登录

```
用户重新登录
  ↓
调用 _setJPushAlias(newUser)
  ↓
设置新别名 = 新用户ID
  ↓
✅ 可接收广播推送
✅ 可接收新用户的定向推送
```

## 为什么保留广播推送能力？

### 业务需求

1. **系统公告**：应用更新、维护通知等
2. **活动通知**：全局活动、节日活动等
3. **安全提醒**：安全漏洞、隐私政策更新等

### 用户体验

- 未登录用户也应该能收到重要的系统通知
- 退出登录≠卸载应用，仍是潜在用户
- 广播推送可以引导用户重新登录

### 技术考虑

- `stopPush()` 会完全停止推送服务
- 重新启动推送服务需要较长时间
- 保持推送服务运行，只切换别名更轻量
