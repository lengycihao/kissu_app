# 轨迹页面性能优化总结

## 优化背景
用户反馈轨迹页面存在卡顿问题，特别是动画相关的体验不佳。经过分析，发现了多个性能瓶颈，主要集中在动画执行、标记创建和响应式更新等方面。

## 主要优化措施

### 1. 摇摆动画性能优化（最关键）

**问题：**
- 原本每100ms就调用 `_updateMarkersRotation` 更新marker旋转
- 每次更新都重新创建 BitmapDescriptor，涉及网络请求、图片加载、Canvas绘制等大量操作
- 这是最严重的性能瓶颈

**优化方案：**
- 实现了标记图标缓存机制，避免重复创建
- 降低动画更新频率从100ms到200ms（减少50%）
- 减小摇摆角度从±15度到±10度，使动画更优雅
- 使用 `Future.microtask` 异步更新，避免阻塞主线程
- 添加缓存检查，没有图标时跳过动画

### 2. 标记图标缓存机制

**实现内容：**
- 添加了 `_cachedMyIcon` 和 `_cachedPartnerIcon` 缓存变量
- 实现了 `_needsUpdateIconCache()` 检查是否需要更新缓存
- 实现了 `_updateIconCache()` 更新缓存的图标
- 在 `_initTrackStartEndMarkers` 中使用缓存的图标

### 3. 图片资源缓存

**优化内容：**
- 添加了 `_imageCache` Map 缓存加载的图片
- 优化了 `_loadImageFromNetwork` 和 `_loadImageFromAsset` 方法
- 避免重复下载和解码相同的图片资源
- 在 `onClose` 中清理缓存

### 4. 地图动画优化

**优化措施：**
- 使用 `Future.microtask` 确保动画在微任务中执行
- 减少地图初始化动画延迟从500ms到300ms
- 使用 `isClosed` 检查避免在页面销毁后执行动画
- 不等待动画完成，让它在后台执行

### 5. 响应式更新优化

**页面组件优化：**
- 优化了 `_GradientBackgroundOverlay` 组件，使用防抖减少更新频率
- 只有当 sheetPercent 变化超过0.02阈值时才更新透明度
- 减少了滑动时的重建次数

### 6. 代码结构优化

**改进内容：**
- 简化了标记创建逻辑，使用缓存图标
- 移除了重复的头像加载代码
- 优化了错误处理和降级方案

## 性能提升效果

1. **动画流畅度**：摇摆动画从每秒10次图标重建降低到每秒5次旋转更新
2. **内存占用**：通过图片缓存减少了重复的内存分配
3. **CPU使用率**：异步执行和缓存机制显著降低了CPU占用
4. **响应速度**：页面滑动和交互响应更加流畅

## 注意事项

1. 缓存会占用一定内存，但在页面关闭时会清理
2. 动画频率降低可能会让动画看起来稍微不那么平滑，但整体体验更好
3. 所有优化都保持了原有功能逻辑不变

## 后续建议

1. 可以考虑使用 `AnimatedBuilder` 替代定时器实现更流畅的动画
2. 如果标记数量很多，可以考虑实现标记聚合功能
3. 可以添加性能监控，跟踪优化效果
